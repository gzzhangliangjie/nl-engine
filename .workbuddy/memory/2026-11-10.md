## CRLF 假阳性根修（.gitattributes，commit `cbde0c9`）

- 用户拍板走 `.gitattributes` 路线。全仓库扫描实证：**0 个 CRLF blob**（1440 i/lf + 354 i/-text），受影响的是 `core.autocrlf=true` 检出行为——153 份 tsv/log 中 146 份检出后变 CRLF。
- **靶向规则勿全局**：`*.tsv` / `*.log` / `provenance.txt` → `text eol=lf`（工具生成的数据产物，FNV/逐字节对拍都按 LF）；`*.bat` → `text eol=crlf`（cmd goto/label 依赖 CRLF）。**禁全局 `* text=auto eol=lf`**（会把 .bat 翻成 LF 炸掉批处理）。blob 全 LF → 不需要 renormalize，blob 层零改动。
- **重检出坑（下次直接用结论）**：加 attributes 后 `git checkout -- <paths>` 和 `git checkout-index -f --stdin` 都因 stat 缓存判定「未变」跳过重写（no-op）；**可靠做法 = 删工作文件后 `git checkout --` 从 index 恢复**（工作树干净时确定性安全）。164 份全部转 w/lf。
- 验证：`check-phys-regression.py` exit 0 五基线全 byte-identical（p2 跨目录对不再假 FAIL）；`audio-tools selftest` 46/46 PASS（provenance FNV 场景修复）。
