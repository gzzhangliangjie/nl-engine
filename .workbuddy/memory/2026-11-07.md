## M0.6 GPU 帧内计时（NVRHI timestamp query）——S0 后能力补齐第一版，tag `m0.6`

- 用户确认后续路线：S0 后按「一个版本一件事」走能力补齐序列——M0.6 GPU 计时（已做）→ M0.7 高模资产生成器（S1 命门：Suzanne 504 tri 无法演示切簇）→ M0.8 线框/调试着色 → M0.9 一键回归总闸；vendored meshoptimizer 作对照基准随 M0.7（文档级，不入构建）。Carrot 实查：meshoptimizer + meshlet 是 2023-11-25 同一个大提交 `4c100761` 进的，无截图 MD5 回归（只有 gtest），性能靠 tracy/PIX runtime、无 timer query——M0.9 是超它的部分。
- 实现：`renderer/src/gpu_timer.hpp` 共享 `GpuTimer`（4 slot 环形 `ITimerQuery`，ensure 懒建 / poll 不阻塞 / 无空闲 slot 本帧不计时）；两后端 `begin()` 在 `cmd->open()` 后、`end()` 在 `close()` 前；`HudFrame` 加 gpuMs/gpuMsHistory/gpuTimingAvailable；HUD 加 `GPU x.xx ms (NVRHI timer)` 行 + gpu ms 曲线（面板上限 400→460、曲线 44/34 px 防裁底）；selftest 并入秒→ms 换算与游标回绕（仍 14/14）。
- 关键坑：**deterministic 模式 renderer 不得写回真实 GPU ms**（viewer 已填固定 0.63 ms 样本），否则基线 MD5 每次不同；**基线必须用与 cases.json 用例完全相同的参数**——基线曾用默认 pitch 9.2 而用例是 `--pitch 9`，回放 baselineMatch=False、16.9 万像素全图级差异，差点误判成渲染坏了。
- 实测：两后端 build + selftest 14/14 + ctest 100%；交互模式首次 resolve DX12 `0.0369 ms` / Vulkan `0.0380 ms`（`gpu timer resolved` 日志，GpuTimer 内 `resolvedOnce_`）；`--no-hud` MD5 仍 `7e528087…`（零 query 路径）；`--check` → `stage=M0.6 cases=3 baselines=4` 退出 0；展示台 `/api/run` 三用例全过（hud 双后端 baselineMatch=True、nohud identical=bytes）。
- 顺手修正 S0-PLAN 台账失实：M0.3 四条 checklist 与 `slangc -h` 实际早已完成，`[ ]` 改 `[x]`。
- DX12 `end()` 编辑曾误删 `executeCommandList` 与 fence 注释，下一步立即补回；selftest 阶段校验写死「M0.5」导致 13/14，改为跟随 `kStage` 校验 M0.6。
