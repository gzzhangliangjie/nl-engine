## M0.2 NVRHI device + swapchain 双后端验收（收尾 commit `46f0a30`，tag `s0-device` `155089d`）
- 代码：`renderer/src/backend.hpp`(Backend 抽象) + `backend_dx12.cpp` + `backend_vulkan.cpp` + `png_writer.cpp`(GPU 回读写 PNG)；扩展 core/window(`nativeHandle`/`consumeResize`)、renderer、viewer(`--screenshot`/`--resize` 回归)；`CMakeLists.txt` Vulkan 分支接 nvrhi_vk + vulkan-headers + `VK_USE_PLATFORM_WIN32_KHR`。
- **零 vulkan-1.lib**：本机无导入库、核心函数也无静态导出符号；`LoadLibraryW(L"vulkan-1.dll")` + `GetProcAddress("vkGetInstanceProcAddr")` 引导，22 个 Vulkan 函数指针(核心+KHR)全运行时解析。NVRHI 强制 `VULKAN_HPP_DISPATCH_LOADER_DYNAMIC=0`，故纯 C 指针，不用 vulkan.hpp 派发器。
- **命名三前缀(用户认可)**：`vulkan*_`=原生句柄、`nvrhi*_`=NVRHI 抽象层、`vk*_`=运行时函数指针；原 `vkDev_`/`vkDevice_` 只差两字母被否。
- **退出段错误 139 根因+修复**：NVRHI `Device::~Device()` 用非拥有的 `vk::Device` 包装销毁内部 query pool/pipeline cache/descriptor set layout，但**全源码无 `vkDestroyDevice`**——VkDevice 只由本后端销毁。原 `shutdown()` 先 `vkDestroyDevice_` 后 `nvrhiDeviceHandle_.Reset()`，导致 NVRHI 析构作用于已销毁 device → use-after-free。改为先 `Reset()` NVRHI 句柄再销毁原生对象，退出码 0。
- **present 阶段 OUT_OF_DATE_KHR**：resize 后 present 过期被当硬错致验收失败；按标准 Vulkan 实践 `recreateSwapchain()+createTargets+return true`(不计错误)，与 acquire 阶段一致。
- 验收：DX12/Vulkan 两后端 `viewer --screenshot --frames 8` 均 `shutdown ok deviceErrors=0`、退出 0；`m0.2-vulkan.png` 与 `m0.2-dx12.png` **MD5 完全一致**(`bdebaf50...`) 验证通用管线；resize 640x360→1024x768 前后 PNG 非黑。截图证据 `docs/screenshots/`。
