# M0.9 计划 — 一键全量回归总闸

> 状态：**执行中（2026-11-07）**。0.x 必做序列的最后一版，做完立刻进 S1 切簇。

## 目标

一个命令跑完 **`example/cases.json` 里全部版本的全部用例 × 双后端**：历史里程碑的 exe 从 tag 快照现场重跑，当前版本从当前 build 重跑；每张 PNG 与归位基线逐字节比对，每个 selftest 校验日志，每次运行校验 `deviceErrors=0`。**全绿才 exit 0**——这就是 S1 起每次改动后的总闸：一条命令回答「历史用例有没有被我改坏」。

## 能亲眼看到的用例

- `python tools/regression.py` → 控制台逐用例 PASS/FAIL 表 + `build/regression/report.md` / `report.json` 报告。
- 负向证据：故意改坏一个基线字节 → 总闸 exit 1 并指出是哪个用例哪个后端。
- m0.9 自己的可见用例：`gate-hud`——线框 × tri-id × HUD 的**组合状态**冒烟（此前从未同时归位过），外加 selftest 15/15（stage 校验 M0.9）。

## 验收判据

1. `python tools/regression.py` 全量运行：全部可自动用例 × 双后端 PASS，exit 0。
2. 基线比对分档（与展示台同约定）：MD5 相同 = `bytes`；不同但像素差 maxDelta ≤ 1/255 且 ≤ 2 像素 = `near`（GPU 取整噪声，已知于 M0.4 内壁 / resize）；再大 = FAIL。
3. selftest 用例：exit 0 + 日志含 `SELFTEST PASS (n/n)`；带 GPU 的运行 `deviceErrors=0`（无该字段不适用）。
4. exe 缺失 = FAIL 并提示 `tools/showcase/rebuild.py --tags <tag>`，不静默跳过。
5. 负向用例：改坏基线 → exit 1，还原后 exit 0。
6. `python tools/showcase/server.py --check` 退出 0（stage=M0.9）。
7. resize 类用例的 `.before.png` 与 `beforeBaselines` 同样比对。

## 实现要点

- **复用展示台基础设施**：`import server`（同目录）拿 `exe_for / baseline_for / before_baseline_for / validated_params / build_argv / compare_pixels / md5`——单一语义，不搞第二份解析。
- **参数取默认值**：`validated_params(case, {})`，与基线生成时同参。
- 运行产物写 `build/regression/runs/`，不碰展示台 runs 目录；报告写 `build/regression/`。
- 逐运行串行（viewer 开真实 GPU 窗口），`timeout=120s`。
- 报告含 crossBackend 对照（两后端 PNG MD5 是否一致）作为信息档，不参与判分。

## 非目标

- 不做并行运行（GPU 窗口互抢 adapter，串行足够）。
- 不做 CI 远端——总闸先服务本地「提交前一条命令」。
- 不改任何渲染行为：M0.9 是纯工具版本，`--no-hud` 基线必须逐字节不动。
