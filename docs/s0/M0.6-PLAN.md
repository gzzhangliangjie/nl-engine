# M0.6 计划：NVRHI timestamp query（真实 GPU 帧内计时）

> 立项 2026-11-07。**M0.6 起是 S0 之后的能力补齐版本序列**，按「一个版本一个版本来」推进：
> 每个版本只做一件能亲眼看到的事，走完整流程（目标 → 可见用例 → 验收判据 → 放行 → example 归位 → 台账 → 提交 + tag）。
> 本版做 `docs/s0/S0-PLAN.md`「可观测性与调试工具计划」里 **L2 的第一个洞**，不碰 S1 的切簇算法。

## 为什么是这个

- M0.5 的 HUD 只有 `frame ms`，那是 **CPU 帧间隔**，不能用来看 GPU 耗时 / 性能退化（`S4-PLAN` 已挂账）。
- L1 RenderDoc 需要装外部工具，本机未装；L3 Nsight / PIX / PresentMon / Tracy 同理。
- **L2 是唯一纯代码侧、两后端统一、零厂商 SDK 的一层**：vendored `nvrhi.h` 自带 `ITimerQuery`（`createTimerQuery` / `pollTimerQuery` / `getTimerQueryTime` 返回秒 / `resetTimerQuery`），command list 上有 `beginTimerQuery` / `endTimerQuery`。DX12 映射到 `EndQuery`、Vulkan 映射到 `vkCmdWriteTimestamp`，两边都由 NVRHI 封装，图形 API 符号仍不出 `renderer/`。

## 目标

1. 每帧用一对 timer query 包住整帧 GPU 命令，异步轮询得到真实 GPU 耗时（ms）。
2. 结果经 `HudFrame` 双向 POD 送到 HUD，与 CPU 帧间隔**并排显示 + 双曲线**，一眼看出两者不是一回事。
3. `--no-hud` 路径完全不建 query、不碰 GPU 计时，M0.1~M0.5 的基线一个字节都不变。

## 能亲眼看到的用例

交互窗口里 HUD 新增两行：`CPU xx.xx ms   GPU x.xx ms (NVRHI timer)` 以及 GPU 耗时曲线；
转动相机 / 拉近模型时 GPU 数字跟着变，CPU 帧间隔基本不变。

```bash
scripts/build-m0.2.bat DX12          # 或 VULKAN
build/<backend>/viewer.exe --mode normal --hud        # 交互窗口看真实 GPU ms
build/<backend>/viewer.exe --screenshot m0.6.png --frames 8 --hud --size 960x540
build/<backend>/viewer.exe --screenshot base.png --frames 8 --no-hud
build/<backend>/viewer.exe --selftest
```

**截图可复现**：与 M0.5 同一约定——回归模式下 GPU 样本也用固定值并在面板标 `capture/replay (fixed samples)`；交互窗口才显示真实采样。带 HUD 的两后端 PNG 仍因 backend / debug 文本不同而不同，不是 3D 画面不一致。

## 验收判据（放行前逐条过）

- [x] 两后端 HUD 均显示**非零且量级合理**的 GPU ms，`gpuTimingAvailable=true`；`deviceErrors=0`。实测交互模式首次 resolve：DX12 `0.0369 ms`、Vulkan `0.0380 ms`（`gpu timer resolved` 日志），渲染进程 `deviceErrors=0`。
- [x] timer query 按 frame-in-flight slot 轮转，未 resolve 的 query 不复用；轮询失败不阻塞、不报错刷屏。实现：4 slot 环形，`poll` 只取已 resolve 的、绝不阻塞；无空闲 slot 时 `begin` 返回 false 本帧不计时。
- [x] `--no-hud` 正常视角 DX12 / Vulkan PNG MD5 同为 `7e528087d19722d8f9ef4de35e36d382`，与 M0.4 / M0.5 基线逐字节相同（GpuTimer 完全不 ensure/poll/begin/end）。
- [x] `--selftest` 覆盖换算逻辑（秒 → ms）与环形缓冲，两后端通过；`ctest` 100%。`GpuTimer::selfTest()` 并入 HUD selftest 项，仍为 `SELFTEST PASS (14/14)`。
- [x] `example/m0.6/` 归位基线 PNG + `run.bat`，`example/cases.json` 登记版本，`python tools/showcase/server.py --check` 退出 0（`stage=M0.6 version=m0.6 cases=3 baselines=4`）。
- [x] 展示台 `/api/run` 现场回放本版用例：`hud` 双后端 `baselineMatch=True`（`identical=False` 属预期，backend/debug 文本不同）、`nohud` `identical=bytes`、`selftest` `ok=True`。
- [x] 截图 `docs/screenshots/m0.6-hud-{dx12,vulkan}.png`；台账四栏写实追加；提交后打 tag `m0.6`。

**踩坑记录**：基线曾用默认参数（pitch 9.2）生成而清单用例是 `--pitch 9`，展示台回放 `baselineMatch=False`、16.8 万像素差异——教训：**基线必须用与 cases.json 用例完全相同的参数生成**，pitch 一度之差就是全图级差异。

## 明确不做（留给后续版本）

- `--profile` 按 pass 拆分（Scene / HUD 分别计时）→ 后续版本
- RenderDoc `--capture-frame N` 进程内 API → 需要装工具，另排
- 中文字体 / InputText / docking → 与 HUD 渲染无关，按 `docs/IMGUI-GUIDE.md` 的增量表排
- S1 切簇算法 → M1.x，不混进 M0.6

## 放行

以上全过才打 tag `m0.6`、进下一个版本。**验收不过不进下一步**，tag 在验收之后打。
