# M0.8 计划：线框 / 调试着色（normal / UV / 三角形ID）

> 状态：**已确认（2026-11-07）**。序列：M0.6 ✅ → M0.7 ✅ → **M0.8 调试着色** → M0.9 回归总闸 → 进 S1。
> S1 起要「换一种着色看同一个网格」排查切簇 / 剔除 / 边界问题，本里程碑把这双眼睛装上。

## 为什么是它（背景）

- S1 切簇的排查第一步永远是「这个三角形到底在不在、法线对不对、UV 接缝在哪」，
  贴图着色看不出这些。M0.7 的 204,800 tri 纽结用贴图看就是一坨纹理，用 tri-id 看
  才能直接目测密度与朝向。
- 线框是网格工作的第二双眼睛：Suzanne 3,936 tri 的线框可以逐个数，验证索引 /
  拓扑；后续切簇的簇边界线框对照也靠它。
- **全部走 NVRHI 抽象层内**：线框 = 光栅化 fill mode，零几何 shader、零新依赖；
  着色模式 = shader 内分支，`model.slang` 依旧单源出 SPIR-V + DXIL。

## 做什么

### 1. `model.slang`：四种着色模式（一个 PS 分支，不加 entry）

- `g_options.x` = shading mode：`0 textured / 1 normal / 2 uv / 3 tri-id`。
- **textured**：现有路径原样保留（基线逐字节不变的前提）。
- **normal**：世界空间法线 `n*0.5+0.5` 直接当颜色（Suzanne 旋转时看法线朝向）。
- **uv**：`(u, v, 0)` 当颜色；IcoSphereDense 的等距柱状 UV 接缝直接可见。
- **tri-id**：`SV_PrimitiveID` 经整数 hash 出伪随机颜色——同参每次渲染确定，
  不同三角形颜色不同（已实测 slangc 双目标编译通过，见验收记录）。

### 2. 线框：NVRHI `RasterState::setFillWireframe()`

- 不加几何 shader、不重建索引。pipeline 组合从 2 套（solid × cull）扩到
  **4 套（solid/wire × cull back/none）**，着色模式只是 cbuffer 值，与线框正交。
- 深度测试照常开启（wireframe 也参与遮挡，看得到「藏在后面的线」关系）。

### 3. 参数与 HUD

- `FrameParams` 加 `int shading = 0; bool wireframe = false;`（POD，缺省 = 现状）。
- viewer：`--shading textured|normal|uv|tris`、`--wireframe`；**V = 线框开关、
  N = 循环切着色模式**（Key 枚举加 V/N，core 零图形符号纪律不变）。
- HUD：`shading` 下拉框（imgui_widgets 已 vendored，Combo 可用）+ `wireframe`
  复选框，双向 POD 通道与 cull/color 控件同一条路；面板高度上限按实拍复核。

### 4. example 归位（硬规则，老流程）

- `example/m0.8/`：4 个 pair 用例 + selftest，双后端基线 PNG + `run.bat` + cases.json。
- `renderer.cpp` 的 `kStage` 改 M0.8；`python tools/showcase/server.py --check` 退出 0。
- 展示台侧：m0.7 的 exe 映射改指 `build/showcase/m0.7/` 快照并 `rebuild.py` 补建
  （新版 exe 挤占 `build/<backend>/` 的例行腾位）。

## 验收判据

1. 四种着色 + 线框在**双后端**都出正确画面、`deviceErrors=0`、调试层零输出。
2. **不带新参数时行为与 M0.7 完全一致**：Suzanne `--no-hud` 基线 PNG MD5 仍为
   `7e528087…`，selftest 14/14（stage 检查改 M0.8）。
3. `model.slang` 单源出 SPIR-V + DXIL（`SV_PrimitiveID` 双目标实测编译通过，
   魔数核对照旧走 selftest 8/8）。
4. HUD 的 shading combo / wireframe 复选框改值 → 画面即时变化（与 CLI 同一条
   FrameParams 路径）；960×540 实拍面板完整不裁底。
5. `example/m0.8` 归位 + cases.json + `--check` 退出码 0。

## 踩坑预判

- **SV_PrimitiveID 的签名匹配**：PS 直接收 rasterizer 生成的系统值，VS 输出不含
  它——D3D 签名匹配允许（system value 注入）；SPIR-V 侧对应 `gl_PrimitiveID`
  内建，Vulkan fragment 合法。风险点是 NVRHI validation 或 DX12 debug layer 对
  签名的额外校验，实跑即知。
- **HUD 面板高度**：M0.6/M0.7 的教训——每加一行都可能裁底。combo + checkbox
  尽量并行布置，加完必须 960×540 实拍确认。
- **tri-id 颜色的确定性**：用整数 hash（无浮点随机源），同参数两次渲染 PNG 一致，
  截图回归可用。
- **线框 + tri-id 同开**在密集网格上是高频率噪点——属预期，不是 bug；用例里
  不做这个组合的基线。

## 不做什么（边界）

- 不做按簇着色 / 簇边界线（S1 的事，tri-id 是它的地基）。
- 不做 barycentric wireframe（fragment shader 手搓线宽）；光栅 fill mode 够用。
- 不做 `--profile`、HUD 资源统计等穿插项。
