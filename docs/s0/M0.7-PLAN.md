# M0.7 计划：高模测试资产生成器（S1 切簇的命门）

> 状态：**已确认（2026-11-07）**。用户选定：生成器两种形状都实现，
> **example 主用例 = 环面纽结、约 20 万 tri 档**。
> 序列：M0.6 ✅ → **M0.7 高模资产** → M0.8 调试着色 → M0.9 回归总闸 → 进 S1。

## 为什么是它（背景）

S1 的核心是切簇（meshlet/cluster）。Suzanne 只有 3,936 个三角形，切了前后看不出区别，
任何 S1 用例都不成立。需要现在就有一只**致密网格**（10 万~50 万 tri），同时：

- M0.6 的 GPU 计时第一次派上用场：大模 vs Suzanne 的 GPU ms 对比，可见倍数差。
- M0.8 的调试着色要「换一种着色看同一网格」，也得有大模才看得出门道。
- `meshoptimizer`（簇生成的工业标准实现）随本版本 vendor 进 `thirdparty/`，
  作**文档级对照基准**（将来我们的切簇结果与它对照簇数/边界三角数），**不入构建**。

## 做什么

### 1. `scripts/gen-dense-mesh.py`：程序化致密网格生成器

- **纯 Python 标准库**（zlib/struct 手写 PNG + GLB 打包，复用 pack-suzanne-glb.py 的
  bufferView 封装套路）。**零网络、确定性**：同参数两次生成，GLB MD5 相同（无随机源，
  浮点运算顺序固定）。
- 形状：`--shape icosphere | torusknot`（细分球 / 环面纽结），`--subdiv N` 控制密度，
  目标覆盖 10 万~50 万 tri 档位。
- 顶点属性：POSITION / NORMAL / TEXCOORD_0（程序化 UV）；索引 **uint32**
  （顶点必超 65535）。
- 贴图：内嵌一张程序化生成的**棋盘格 PNG**（不是照片贴图，但能验证 UV 连续性，
  也是 M0.8 调试着色的视觉参照）。
- 产物落 `assets/models/<名字>.glb`，运行时仍由 `NL_ASSET_DIR` 注入，不依赖 CWD。

### 2. `--model` 参数（唯一必须动 C++ 的点）

- 现状：`scene.cpp:138` 硬编码 `NL_ASSET_DIR "/Suzanne.glb"`。
- 改法：viewer→core→renderer 传 `--model <文件名>`；scene 只做**白名单校验**
  （只允许 `assets/models/` 下已存在的 .glb 文件名，拒绝路径分隔符），默认值仍是
  `Suzanne.glb`。
- **不带 `--model` 时行为与 M0.6 完全一致**——旧基线 PNG 一个字节都不动。
- HUD / 日志自证加载的是哪个模型：日志已有 `model ready: ... vertices=...`；
  HUD 增 model 名 + tri 数一行（截图直接看得到，不用翻日志）。

### 3. vendored meshoptimizer（文档级，不入构建）

- 落 `thirdparty/meshoptimizer/`（gh-proxy 浅克隆，零 SDK 性质依赖）。
- CMakeLists **零引用**；README/thirdparty 说明里标注用途 = S1 切簇正确性对照。

### 4. example 归位（硬规则，老流程）

- `example/m0.7/`：dense 模型基线 PNG（双后端，`--hud` 含 model/tri 行）+ `run.bat`。
- `example/cases.json` 登记；`renderer.cpp` 的 `kStage` 改为 M0.7；
  `python tools/showcase/server.py --check` 退出码 0 才算验收。

## 验收判据

1. 同参数两次生成 GLB MD5 相同；生成过程零网络、纯 stdlib。
2. 输出 tri/vert 数与理论值一致，且 HUD / 日志自证（`--model` 指向 dense 模型时可见）。
3. `viewer.exe --model <dense>` 双后端截图成功、`deviceErrors=0`；HUD GPU ms
   与 Suzanne 同口径对比，倍数差记录进台账（观察项，不作硬指标）。
4. **不带 `--model`：Suzanne 的 `--no-hud` 基线 PNG 逐字节不变**，selftest 仍 14/14。
5. `example/m0.7` 归位 + cases.json + `--check` 退出码 0；`--check` 仍以 kStage 判阶段。
6. meshoptimizer 在 `thirdparty/` 就位，但 CMake 零引用（grep 可证）。

## 踩坑预判

- **uint32 索引**：已核实无坑——load 侧接受 componentType 5125，管线侧本就
  R32_UINT（scene.cpp:194/333）。
- **GLB 体积**：50 万 tri ≈ 位置 12B + 法线 12B + UV 8B/顶点，约 15~20 MB 单文件，
  tinygltf 加载时间可能可感（几百 ms 级），如实记录不影响验收。
- **std::vector 拷贝**：大模上传路径 `indices` 先转 uint32 容器再 memcpy，
  内存峰值 ~3×GLB 几何量，量级可接受，真顶不住再改（不预优化）。
- **PNG writer 确定性**：zlib 压缩输出在同机同版本 Python 下确定；MD5 判据在本机
  成立即可，不承诺跨 zlib 版本一致。

## 不做什么（边界）

- 不做多模型同帧多 draw（S1 的事）。
- 不做 `--profile` pass 拆分、HUD 资源统计（⑤⑥穿插项，另行安排）。
- 不动 meshoptimizer 的任何源码，不让它进构建。
