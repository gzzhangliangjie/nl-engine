## 升格流程（固化，五步）

1. **案发即登记**：任何流程纪律坑，**当批交付前**在下表追加一行（日期/案发处/坑点族/根因一句话/处理）。close/release 文档闸把关：收口批有案发未登记 = 报表 ③b 行暴露。
2. **第二次=当场升格**：登记前先查同族历史行——该族已有一次记录的，**当场**把禁令写进 AGENTS 纪律条目（措辞用「**禁 X**」，禁止写成「注意/建议/尽量」），机理细节留在台账。
3. **同族按机制归类**，不按表象：例——「前台超时转后台弃养」「秒级活串链尾」「后台无预期时长」同属**后台弃养**族；「cwd 漂移」「env 前置未核」同属**换树前置未核**族。
4. **红线级再犯**：交付摘要必须单列一节交代（根因 + 为何禁令没咬住 + 补什么闸），不许只在流水账带过。
5. **条目不撤销**：机理变化使禁令过时时，标「口径修订」改写并留史，不删行。

## 机械拦截区（闸自动落账，非案发）

闸拒绝 ≠ 案发：被闸拦住说明闸有效，自动落账不进案发表。**台账两份来源**：
① `.workbuddy/gate-blocks.log`（仓库侧，一行一拒：时间/gate/cwd/reason）——wt_gate（check-build/check-cmd 全部拒绝路径）+ pre-commit（master 提交拦截）写入；② `~/.workbuddy/hooks/gate-blocks.log`（会话级，`时间 | rule | cwd | cmd`）——wt_tree_gate（TREE/TREE-BYPASS）+ nl_ops_gate（R1~R4/R*-BYPASS）写入。`wt_pool close` 报表 ③b 行挂累计数。

**统计入口（2026-11-14 落地）**：`python ~/.workbuddy/hooks/gate_report.py`——汇总两份台账（按规则计数 + 今日计数 + 最近明细），**同族 ≥2 案自动标升格提示**（对应本文件升格流程第 2 步）。案发 = 闸没拦住、事后人工发现（或用户点名）的流程坑，进上表。
