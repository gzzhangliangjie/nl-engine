00 · Positioning

为什么选 Unity 当宿主，以及这份手册怎么用

Unity 没有官方 Nanite/Lumen 等价物——这既是坏消息（一切要自研），也是好消息（你有完整的自研空间，且能长在日常工具链上）。

先说清楚 Unity 能给你什么、不能给什么

✅ 现成可白嫖的

· 自定义 SRP：整个渲染管线的组织权在你手里
· Unity 6 的 GPU Resident Drawer + GPU Occlusion Culling：实例级 GPU-driven 剔除
· RenderGraph：UE 式渲染图的官方实现
· Burst/Jobs：离线预处理可以跑到接近原生速度
· ComputeShader / GraphicsBuffer / indirect 绘制全套

❌ 必须自研的

· 虚拟几何：切簇、DAG、误差选层、簇级剔除——全都没有
· 动态 GI：只有 APV（Adaptive Probe Volumes，烘焙探针）和屏幕空间方案
· 可见性缓冲与材质解析
· 软光栅（且受原子操作平台差异制约）

前置要求：本手册只讲「Unity 这一侧怎么做」，算法原理不在重复——切簇/DAG/vis buffer/探针 GI 全部见主知识库 index.html 的 01、02、04 章，手册里用「见主库 §x.x」标注。C# 与 Unity 基础假定你已有（你日常就在用 Unity）。

三个设计决策先定下来

决策点推荐理由
URP 插件 vs 裸 SRP裸 SRP（自定义 RenderPipeline）你要控制每个 pass，URP 的内置逻辑反而是干扰；catlikecoding 教程也按这个路线教
RenderGraph vs 手工 pass先用手工 pass，U5 之后再迁 RenderGraphRenderGraph 学习曲线陡，先跑通再现代化
离线预处理形态编辑器内 Burst job + 自定义资产不引入外部工具链，切簇结果随导入管线自动刷新，和你现有 CI 也兼容
01 · Capability Map

Unity 6 能力盘点

把可用的积木摆出来，标注成熟度——知道边界在哪，路线才不会设计歪。

GPU-driven 基建

能力现状与边界
BatchRendererGroup最底层的 GPU-driven 批处理 API：自己维护 batch 元数据， Unity 只负责画。GPU Resident Drawer 就建在它上面。做簇级剔除时你大概率要直接用它或绕开它
GPU Resident DrawerUnity 6 起内置（URP/HDRP）：静态网格实例自动进 GPU-driven 路径，实例剔除在 GPU 完成。解决的是实例级问题，不碰你的簇级需求，但可以作为对照实验
GPU Occlusion CullingUnity 6.1 起的官方遮挡剔除，同样是实例级。值得读它的文档理解 Unity 的实现取向
RenderMeshIndirect带材质/光照变量的 indirect 绘制，是簇绘制的首选入口；DrawProceduralIndirect 更底层，适合 vis buffer 直写

数据与计算

能力现状与边界
Mesh APIMesh.AllocateWritableMeshData / ApplyAndDisposeWritableMeshData：Burst 友好的网格读写，离线切簇用它，不要用老 API 逐顶点改
Burst + IJobParallelFor切簇/QEM/建 DAG 的 CPU 侧全部 Burst 化，性能接近 C++；注意 NativeArray 生命周期与安全系统开销（用 Allocator.TempJob + collect）
GraphicsBufferStructuredBuffer / AppendBuffer / IndirectArguments 全有；注意 16 字节对齐习惯与 SetData 上传节奏
AsyncGPUReadback延迟一帧回读簇列表的标准姿势（对应主库 §3.3 的回读优化）
ComputeShader 64 位原子平台相关，HLSL 的 InterlockedMax 对 64 位支持取决于图形 API 与编译目标。U3 阶段必须先验证，不行就用双 32 位 CAS 模拟

光照现状（为什么 GI 只能自研）

Unity 的 GI 方案是 APV（Adaptive Probe Volumes）——烘焙的探针体积，加上 HDRP 的屏幕空间/RTGI 补充。没有 Lumen 那种「动态、全场景、增量更新」的间接光。所以主库 02 章的 screen probe + world cache 设计在 Unity 里是零到一的自研，没有官方半成品可蹭。

03 · Roadmap

学习路径 U0 ~ U8

九个阶段，每个都有独立验收标准。前置理论全部指向主知识库对应章节。

  1. U0 · 自定义 SRP 最小闭环

    裸 RenderPipeline：清屏 → 画一个 mesh → 相机矩阵。不做任何优化，只确认「渲染管线组织权在我手里」。

    验收：场景里任意转相机画任意模型，无 SRP Batcher 依赖。

  2. U1 · Deferred GBuffer

    GBuffer pass（albedo/normal/roughness/depth 多 RT）+ 一个最简单的光照 accumulate pass。这是后面 vis buffer 反解 GBuffer 的对照物。

    验收：GBuffer 各通道调试图正确，光源能点亮场景。

  3. U2 · compute 通路打通

    写一个最简单的 compute：读 buffer → 写 buffer → AsyncGPUReadback 回读验证。同时跑通 AppendBuffer → indirect args → DrawProceduralIndirect 画 100 万个点。

    验收：回读数值正确；100 万点 indirect 绘制无 CPU 参与。

  4. U3 · 64 位原子验证（关键卡点）

    最小用例：compute 里对同一地址 InterlockedMax 一个 pack 过的 uint64（深度+id），回读验证。这一步决定 vis buffer 用哪种实现。

    验收：目标平台（你的开发机 + 发布目标）验证通过，或确定了 2×32 位 CAS 退路。

  5. U4 · 离线切簇工具

    Burst job 实现切簇（贪心连通性生长即可，先不用 METIS）+ QEM 简化 + DAG 构建，AssetPostprocessor 挂钩，导入 mesh 自动生成 .clustermesh 资产。对应主库 §1.3 全部五步。

    验收：百万面模型导入即产出层级，编辑器窗口可视化各层簇（随机着色）。

  6. U5 · 簇剔除 + indirect 绘制

    compute 做视锥剔除（簇包围球）→ 压缩存活列表 → 填 indirect args → 绘制。加上 cluster 调试图与「冻结剔除」调试开关。

    验收：单级簇能画出来且剔除正确；关掉剔除帧率变化符合直觉。

  7. U6 · DAG 遍历 + 屏幕误差选层

    把主库 §4.1 的伪码翻译成 Unity compute：投影误差、从根向下、满足即停。多分辨率窗口对照测试（4K/1080p 阈值行为）。

    验收：近细远粗自动切换，切换处无裂缝（回查锁边界），LOD 色阶调试图正常。

  8. U7 · vis buffer + Hi-Z

    先上 vis buffer（用 U3 验证过的原子方案）+ 材质解析替代 U1 的直写 GBuffer；再加 Hi-Z 金字塔与簇级遮挡剔除（上一帧深度，两遍法）。

    验收：材质解析结果与 U1 的 GBuffer 逐通道一致；遮挡剔除有帧率收益且无漏画。

  9. U8 · 探针 GI demo

    主库 02 章的简化方案落地：GBuffer → 屏幕探针（4 cascade 八面体）→ 命中查世界缓存（开放寻址 hashmap）→ final gather → 时间累积 + 双边滤波。光追入口先用最简单的「射线步进自定义 SDF」或仅直接光 + 单跳。

    验收：室内有颜色渗透；关灯余晖自然衰减；移动无明显拖影。

顺序别乱：U3 看似枯燥但决定 U7 的技术选型，务必提前；U4 是纯 C#/Burst，可以和 U2/U3 并行做；U8 之前不要碰任何「好看」的东西，先保证管线每一层都可视化正确。
04 · Unity-specific Pitfalls

Unity 特有踩坑

主库 07 章的通用坑之外，Unity 宿主还会给你这几个专属惊喜。

现象原因处理
64 位原子编译不过/行为异常图形 API 与 shader 编译目标差异（DX11 不支持，DX12/Vulkan 才有）U3 最小用例先行；退路 2×32 位 CAS 循环，或把 vis buffer 拆成两张 RT32（深度一张、id 一张，接受额外一次同步）
GPU buffer 数据错位C# struct 布局与 HLSL cbuffer 对齐规则不一致（尤其 float3 + float 混排）所有跨端结构按 16 字节对齐设计；[StructLayout(LayoutKind.Sequential)]；用 UnsafeUtility.SizeOf 断言
indirect 绘制没被 SRP Batcher 合批程序化绘制不走 SRP Batcher，这是正常的别指望合批，你的性能模型是「一次 indirect 画全部簇」；材质差异走 vis buffer 解析
Burst job 卡在安全系统NativeArray 越界检查、依赖图等待编辑器下用 Jobs Debugger 找真问题；发布构建确认 Burst 编译生效（BurstCompiler 选项）
Editor 和 Player 表现不一致编辑器渲染走额外 debug/preview pass；异步 script compilation 干扰关键 pass 只在 RenderPipelineManager 的标准回调里做；定期用 Build 而不是 Editor 验证
RenderMeshIndirect 的光照变量不生效它需要显式提供 MaterialPropertyBatch / light data自研管线里干脆自己传 per-cluster 数据 buffer，别用它内置的简化光照
深度金字塔不能用 GenerateMipsGenerateMips 是双线性（均值），遮挡剔除需要最大值滤波自写 downsample compute，逐级取 max；宽高为奇数层注意边界 clamp
AsyncGPUReadback 回读是旧帧数据本来就该如此——回读天然滞后这不是 bug，主库 §3.3 的「延迟一帧」方案就是靠它；把同步点设计进管线而不是试图消除
